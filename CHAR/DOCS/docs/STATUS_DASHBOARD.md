# 🎨 Live Status Dashboard — Persona-Tailored Views

**Location:** `docs/status.html`  
**Type:** Self-contained HTML (no external dependencies)  
**Data:** Auto-refreshes from `docs/status/*.json`

---

## 🎯 Overview

The status dashboard provides **persona-tailored views** of project status:

- **Project Manager** — KPIs, pass rates, schedule tracking
- **Implication Agent** — Scope deltas and downstream impacts
- **Project Verifier** — Test lanes, gates, failing buckets
- **Stakeholder** — Roadmap and outcomes at a glance
- **You (Operator)** — Next actions + ECRR loop status

---

## 🚀 Quick Start

> **Default workflow:** open `docs/status.html` directly from disk. The dashboard is built for local-first "file mode"; handing it to the Next.js dev server triggers routing errors.

### ✅ Primary: File Mode (works perfectly)

```powershell
# Open the HTML file directly (Firefox or any modern browser)
start firefox docs/status.html

# Click "Load files"
# Select: docs/status/roadmap.json, tests.json, ssot.json
```

**Why file mode?**
- ✅ No server to run or stop
- ✅ Zero port conflicts or CORS surprises
- ✅ Works completely offline
- ✅ Keeps the dashboard 100% local-first
- ℹ️ `Load files` reads the JSON straight from `docs/status/` when the page is `file://`

### 🪄 Static file server (optional)

Use this only if you want auto-refresh without clicking `Load files`.

```powershell
# Serve the docs directory with a dumb static server
cd docs
python -m http.server 3003

# Open in browser
start firefox http://localhost:3003/status.html

# Then enable the "auto (30s)" checkbox for live polling
```

> ⚠️ Skip `npm run dev` / Next.js here. The framework tries to hydrate `status.html` as an app route and returns HTTP 500.

### ⚙️ Integrating with another host

```powershell
# If you must proxy through another server, expose docs/status/*.json
# Update the Endpoint field inside the dashboard to match that base URL
# Default expectation remains: http://localhost:3003/status/
```

## 📊 Data Flow

### Automatic Generation

The roadmap automation **automatically generates** dashboard JSON files:

```
pnpm roadmap:update
  ↓
EXAMINE → Parse test results
  ↓
CLEAN → Compute statuses
  ↓
REPORT → Generate Markdown + Dashboard JSON
  ↓
docs/status/roadmap.json  ← Simplified roadmap
docs/status/tests.json    ← Test stats + failing buckets
docs/status/ssot.json     ← Build snapshot
```

### File Formats

**`docs/status/roadmap.json`** — Simplified roadmap structure:
```json
{
  "M1 Foundations": [
    ["Instant Practice (/try)", "green"],
    ["Warmup FSM + Reflection", "green"]
  ],
  "M1.5 Hardening": [
    ["PR Test Lane (smoke+pilot-core)", "green"],
    ["Accessibility smokes", "yellow"]
  ]
}
```

**`docs/status/tests.json`** — Test summary + failing buckets:
```json
{
  "updatedAt": "2025-10-01T08:00:00Z",
  "prLane": { "total": 120, "passed": 118, "failed": 0, "skipped": 2 },
  "nightly": { "total": 520, "passed": 150, "failed": 340, "skipped": 30 },
  "buckets": [
    { "tag": "@dashboard", "failed": 80, "examples": ["Test 1", "Test 2"] }
  ]
}
```

**`docs/status/ssot.json`** — Build snapshot:
```json
{
  "buildSha": "a1b2c3d",
  "cohort": "pilot",
  "when": "2025-10-01T08:00:00Z",
  "notes": "Generated by ECRR roadmap automation"
}
```

The dashboard is fully integrated with the roadmap automation:

### Automatic Updates

```bash

pnpm roadmap:update

# Generates:
# - docs/ROADMAP*.md (Markdown)
```

When the GitHub Actions workflow runs:
1. Tests execute → JSON reports
2. ECRR automation runs
3. **Dashboard JSON updated** automatically
4. Docs committed to repo
5. Dashboard shows latest status on next page load

## 🎯 Persona Views Explained

### Project Manager
- PR lane pass % — Must stay ≥95% (gate requirement)
- Nightly pass % — Can be lower (broader coverage)
- Roadmap snapshot — Green/Yellow/Red feature counts
- Top failing bucket — Where to focus effort

### Implication Agent
- **Blocked dependencies** — What's holding up what
- **Scope impacts** — If X stays Red, Y is delayed
- **Risk callouts** — Privacy UX, customer experience limits

### Project Verifier
- **PR gates** — Must-pass tags: `@smoke`, `@pilot-core`, etc.
- **Quarantined tests** — Nightly-only (can fail without blocking)
- **Flake policy** — Max failures, artifact retention

### Stakeholder
- **Shipped** — Features live in production
- **In progress** — Features under development
- **Planned** — Future milestones

### You (Operator)
- **Next actions** — Specific tasks to complete
- **Priority fixes** — What's blocking progress
- **Tag enforcement** — Keep PR lane clean

## 📋 Troubleshooting

### Dashboard shows demo data

**Cause:** Can't fetch JSON files from endpoint  
**Fix:**
- Verify endpoint URL is correct
- Check files exist: `ls docs/status/*.json`
- Serve via HTTP: `python -m http.server 3003`
- Or use "Load files" button

### CORS errors

**Cause:** Opening `file://` but trying to fetch  
**Fix:** Serve via HTTP or use "Load files" button

### Old data showing

**Cause:** Cache or auto-refresh disabled  
**Fix:**
- Click "Refresh" button
- Enable "auto (30s)" checkbox
- Clear browser cache (Ctrl+F5)
