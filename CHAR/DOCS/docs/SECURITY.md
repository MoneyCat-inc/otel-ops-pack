# Security Policy

## 🔒 Security Overview

This document outlines the security practices, vulnerability reporting procedures, and supply chain security measures for the codex-local observability subsystem.

## 🛡️ Security Measures

### Supply Chain Security

- **Software Bill of Materials (SBOM)**: Generated using CycloneDX format
  - Location: `docs/sbom/codex-local.cdx.json`
  - Updated: On each release and major dependency change
  - Generated by: `pnpm agent:generate-sbom`

- **Artifact Signing**: Critical artifacts are cryptographically signed
  - Status reports: `.agent/status.json`
  - Guardrails reports: `.agent/guardrails_report.json`
  - Badge JSON: Generated by `agent:pr-badge-check -Json`

### Static Analysis

- **CodeQL**: GitHub Advanced Security for vulnerability scanning
  - Workflow: `.github/workflows/codeql.yml`
  - Schedule: Weekly on Mondays at 2 AM
  - Languages: JavaScript/TypeScript

- **GitLeaks**: Automated secrets detection
  - Workflow: `.github/workflows/gitleaks.yml`
  - Schedule: Weekly on Mondays at 3 AM
  - Configuration: `.gitleaks.toml`

### Policy as Code

- **OPA/Rego Policies**: Declarative security and compliance rules
  - Location: `policies/codex.rego`
  - Validation: Integrated with `agent:doctor` and CI pipeline
  - Enforcement: Automated policy checks on every run

## 🚨 Vulnerability Reporting

### Reporting Security Issues

If you discover a security vulnerability, please follow these steps:

1. **DO NOT** open a public GitHub issue
2. **DO NOT** discuss the vulnerability in public channels
3. Email security concerns to: `security@resonai.com`
4. Include the following information:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact assessment
   - Suggested remediation (if any)

### Response Timeline

- **Initial Response**: Within 24 hours
- **Status Update**: Within 72 hours
- **Resolution**: Within 30 days (depending on severity)

### Severity Levels

- **Critical**: Immediate threat to system integrity or data exposure
- **High**: Significant security impact requiring prompt attention
- **Medium**: Moderate security concern with standard timeline
- **Low**: Minor security issue or best practice violation

## 🔍 Security Auditing

### Regular Audits

- **Dependency Audits**: Automated via `pnpm audit`
- **Code Quality**: Continuous via CodeQL analysis
- **Secrets Scanning**: Automated via GitLeaks
- **Policy Compliance**: Real-time via OPA integration

### Audit Artifacts

All security audit results are stored in:
- `.agent/security-audit.json` - Latest audit results
- `.agent/security-history/` - Historical audit reports
- CI/CD artifacts - Automated scan results

## 🛠️ Security Configuration

### Environment Security

- **Secrets Management**: No hardcoded secrets in code
- **Environment Variables**: Validated against allowlist
- **File Permissions**: Restricted access to sensitive files
- **Network Security**: Local-only operations by default

### Agent Security

- **Execution Policy**: PowerShell execution policy validation
- **File Integrity**: Checksum validation for critical scripts
- **Access Control**: Principle of least privilege
- **Audit Logging**: Comprehensive operation logging

## 📋 Security Checklist

Before deploying codex-local in production:
