# Cursor-Assistant Agent Integration

This directory contains the configuration and operational files for the Cursor-Assistant agent, which provides code-aware assistance within the Resonai monorepo.

## Directory Structure

```
.agent/
├── config.json          # Agent configuration and settings
├── agent_queue.json     # Job queue for pending tasks
├── state.json          # Current agent state and context
├── logs/               # Agent execution logs
└── reports/            # Generated reports and analysis outputs
```

## Configuration Files

### `.agent/config.json`
Contains agent behavior settings, safety limits, and operational parameters:
- `max_jobs_per_run`: Maximum number of jobs to process per execution cycle
- `max_files_per_job`: Maximum files to process in a single job
- `max_lines_per_job`: Maximum lines to process in a single job
- `job_ttl_seconds`: Time-to-live for jobs in the queue
- `safety_settings`: Read-only mode, confirmation requirements, file size limits

### `.agent/agent_queue.json`
JSON file containing the current job queue. Jobs are added by the primary agent and processed by Cursor-Assistant.

### `.agent/state.json`
JSON file maintaining the current agent state, including:
- Last processed job ID
- Current context and session information
- Error counts and retry states

## Pausing the Agent

To pause the agent, create a `.agent/LOCK` file:
```bash
touch .agent/LOCK
```

## Progress Feedback Standard

Long-running tasks (>2 seconds) executed by Cursor-Assistant must stream progress using the shared Unicode spinner set (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`) and percentage completion so operators can observe movement in CI logs. Mirror the sample implementation in `AGENTS.md` or wrap loops with a timer helper before new automation ships.

To resume, simply delete the lock file:
```bash
rm .agent/LOCK
```

## Logs and Reports

### Logs (`.agent/logs/`)
- Agent execution logs with timestamps
- Error logs and debugging information
- Job processing history

### Reports (`.agent/reports/`)
- Analysis reports generated by the agent
- Code quality assessments
- Integration test results
- Audit reports and findings

## Usage

The agent operates in **read-only mode by default** and waits for explicit instructions from the primary agent or developer. It can:

- Navigate the codebase and locate files/symbols
- Read and summarize file contents
- Execute safe local scripts and tests
- Prepare patches and diffs (without applying them)
- Generate structured reports

## Safety Features

- **Read-only by default**: No file modifications without explicit instruction
- **Confirmation required**: Agent asks for confirmation before any changes
- **File size limits**: Prevents processing of extremely large files
- **Directory exclusions**: Skips system directories like `node_modules`, `.git`
- **Audit trail**: All actions are logged for review

## Integration with CI/CD

The agent can be integrated into CI/CD pipelines by:
1. Running the agent via `run-agent.ps1` or `run-agent.sh`
2. Processing the job queue automatically
3. Generating reports for review
4. Updating the state file with results

## Troubleshooting

If the agent appears unresponsive:
1. Check for `.agent/LOCK` file
2. Review logs in `.agent/logs/`
3. Verify configuration in `.agent/config.json`
4. Check the job queue in `.agent/agent_queue.json`

For more detailed troubleshooting, see the main project documentation.
