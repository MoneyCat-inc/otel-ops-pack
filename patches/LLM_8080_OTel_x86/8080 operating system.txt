8080 operating system

If you mean **operating systems for the Intel 8080** (the 8‑bit CPU from 1974), here’s the quick lay of the land and how to get one running today.

---

## The main 8080 OS options

* **CP/M (CP/M‑80)** — the canonical choice. Its portability came from a clean split into **CCP** (command processor), **BDOS** (disk/OS services), and a hardware‑specific **BIOS** you tailor to your machine. Only the BIOS depends on your hardware; CCP/BDOS are stock.&#x20;

* **MP/M (Multi‑user CP/M)** — Digital Research’s multi‑user/multi‑tasking CP/M for 8080/8085/Z80 systems. Typical installations needed more RAM and disk and supported multiple terminals. (The MP/M II Programmer’s Guide lists a minimum of an 8080/Z80 and **32 KB RAM**.) ([cpm.z80.de][1])

* **Intel ISIS / ISIS‑II** — Intel’s own development OS for its MDS 8080/8085 systems, shipping with PL/M, assemblers, linker, and tools. Great historically (and for cross‑development), but **not CP/M‑compatible**. ([bitsavers.org][2])

* **Vendor DOSes on S‑100 machines** — e.g., **IMSAI’s IMDOS** (a modified CP/M for the IMSAI 8080), **Heathkit’s HDOS** for the 8080‑based H8/H89 line, and **North Star’s NSDOS** for North Star systems. These were tied to specific hardware but show the diversity of 8080 software ecosystems. ([Wikipedia][3])

> Note: Many later “CP/M‑like” systems targeted the Z80 and use Z80‑specific opcodes. They’ll run on Z80 machines (backward‑compatible with 8080 mnemonics) but **not** on a pure 8080 unless assembled for 8080. (Classic example: Cromemco CDOS was for Z80 systems.) ([Wikipedia][4])

---

## Fastest way to try CP/M right now

* **SIMH AltairZ80**: launch the simulator and at the `sim>` prompt run `do cpm2` to boot CP/M 2.2. ([classiccmp.org][5])
* **z80pack**: a mature 8080/Z80 emulator with ready‑to‑run CP/M environments; clone/build and start the CP/M 2.x script. ([GitHub][6])

(If you want to explore CP/M 3—**the last CP/M for 8‑bit 8080/Z80**—there are curated Altair builds and docs as well.) ([altairclone.com][7])

---

## Bringing up CP/M on your own 8080 hardware (TL;DR checklist)

If you’re building an 8080 single‑board computer or porting CP/M:

1. **Start from a stock BDOS/CCP** and write a tiny loader **GETSYS** to read the system from the first tracks into RAM. The standard build assumes a 20 KB baseline, relocatable upward with MOVCPM (typical systems used 32–64 KB).&#x20;
2. Implement the **BIOS jump table** at **4A00h + b** (where *b* depends on your RAM size). At minimum you need console I/O: `CONST`, `CONIN`, `CONOUT`; disk routines (`SELDSK`, `SETTRK`, `SETSEC`, `SETDMA`, `READ`, `WRITE`) come next.&#x20;
3. Write **PUTSYS** to place your patched memory image (with your BIOS) back on the system tracks; then add a small **cold‑start loader** on track 0 to make it boot.&#x20;
4. On boot, CP/M initializes page zero and jumps into the CCP; you should see the `A>` prompt if your BIOS and disk I/O are correct.&#x20;

---

## Programmer’s cheat‑sheet (CP/M on 8080)

* **Program load address**: **0x0100** (the Transient Program Area start). Even the GETSYS example is coded to start at 0x0100.&#x20;
* **System call gateway**: **CALL 0005h** enters **BDOS**; set **C=function**, **DE=parameter** as needed.&#x20;

**Hello, CP/M (8080 assembly):**

```asm
        org  100h            ; CP/M program entry
        mvi  c,9             ; BDOS function 9 = print "$"-terminated string
        lxi  d, msg
        call 5               ; jump into BDOS via page-zero vector
        ret

msg:    db 'Hello from 8080 on CP/M!$'
```

BDOS function 9 prints the string at DE until `$`. Assemble to a `.COM` (ORG 100h), place on a CP/M disk image, and run. ([Seasip][8])
